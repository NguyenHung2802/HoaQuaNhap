## Goal
n8n gọi `POST /api/v1/posts` để tạo bài nháp/đăng ngay (blog hoặc tin ẩn) kèm ảnh/video; admin quản lý API key.

## Checklist
- [x] `api-keys.service` (key `hq_...`, lưu hash SHA-256, thu hồi, last_used_at giảm tần suất ghi).
- [x] Middleware `apiKeyAuth` (Bearer/X-API-Key, kill switch `news.enabled`, chặn dò khóa 10 lần/5 phút/IP) và rate limit 60 req/phút/key.
- [x] `posts.service` (validate trước, upload sau, dọn media khi lỗi, idempotency `source`+`external_id`, slug duy nhất, token + url_date cho news).
- [x] Route `POST/GET/PUT/DELETE /api/v1/posts` (JSON + multipart `cover`, `images`, `video`); lỗi trả JSON.
- [x] `app.js`: JSON 2MB cho `/api/v1`, 404/lỗi dạng JSON, bỏ truy vấn danh mục cho API.
- [x] Admin `/admin/api-keys` (tạo, hiện key một lần, thu hồi) + mục sidebar.
- [x] Dịch vụ cấu hình `news-settings.service` (cache 30s).
- [x] Tài liệu `docs/12-api-posts.md`, biến `SITE_URL` trong `.env.example` và `config/env.js`.

## Chưa kiểm tra
- Chạy với PostgreSQL thật và Cloudinary thật (cần áp migration S42, `npm install`, khóa Cloudinary trong `.env`).
- Trang `/admin/api-keys` chưa mở trong trình duyệt (cần session admin trên DB thật).
- Chưa có giới hạn IP cho API ở mức ứng dụng (khuyến nghị chặn ở Nginx nếu chỉ n8n nội bộ gọi).

## Rủi ro / ghi chú
- Hai request song song cùng `external_id`: dựa unique constraint, request thua dọn media của mình và trả bài đã có.
- `DELETE` xóa cứng (cascade thống kê); media trên Cloudinary không bị xóa. Gỡ nhẹ nhàng dùng `PUT status=draft`.
- Giới hạn tốc độ nằm trong bộ nhớ: reset khi PM2 khởi động lại.
